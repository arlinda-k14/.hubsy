# Sub-Agent Routing Table

The CMO routes to exactly the sub-agents below and nothing else. The top-level
`config/skills.json` knows `cmo` as a single route target; this file is the CMO's
private registry, the sub-orchestrator layer beneath it. Load it before classifying any
intent.

> Generated by `scripts/sync_subskills.py` from `agents/*/`. Do not edit by hand - edit
> the sub-agent's `SKILL.md` or `agent.json` and re-run the sync.

## Routing map

| Route to | Owns | Intent / signal | Required parameters | Backing skills |
| --- | --- | --- | --- | --- |
| `content-strategy` | campaign concepts, the rolling content calendar, messaging pillars | content calendar, editorial plan, campaign concept, messaging pillars, what should we post, plan the month | `objective`, `program`, `deadline` | `research-assistant`, `humanizer` |
| `social-media` | LinkedIn and Instagram posts, carousels, captions, threads, short clips | linkedin post, instagram post, carousel, caption, social thread, reel, short clip, hashtags | `platform`, `format`, `program` | `social-post`, `social-thread-writer`, `carousel-render`, `clipper` |
| `lead-generation` | prospect discovery, scoring, dedup, staged outreach drafts | find leads, lead generation, prospect, qualify candidates, open to work, career pivot leads, staged outreach | `source`, `limit` | `career-switch-lead-scout`, `scrapegraphai` |
| `analytics` | lead volume, inquiry form completions, cost per lead, underperformer flags | cost per lead, lead volume, form completions, campaign metrics, underperformer, weekly marketing metrics | `campaign`, `window` | `plausible-analytics` |

## Querying rules

1. Match on sub-agent name, then `owns`, then intent signal - in that order of confidence lift.
2. Score in [0.00, 1.00]. `>= 0.80` is a direct match; below that enters the clarification loop.
3. A dispatch touching more than one sub-agent must be split into sequential sub-tasks with an
   explicit order and dependency notes.
4. Never route outside these sub-agents. A non-marketing intent goes back to the orchestrator
   for re-routing.

## Sub-agent contracts

Each sub-agent's full definition and output contract lives in its own file. Read the target
file before dispatching so the payload matches what the sub-agent can actually produce.

- `agents/content-strategy/SKILL.md`  (content-strategy)
- `agents/social-media/SKILL.md`  (social-media)
- `agents/lead-generation/SKILL.md`  (lead-generation)
- `agents/analytics/SKILL.md`  (analytics)

## Adding a sub-agent

Any new marketing skill is created under `skills/cmo/agents/<name>/` with a `SKILL.md`
(and an optional `agent.json` sidecar carrying `owns`, `signals`, `required_parameters`,
and `backing_skills`). Then run `scripts/sync_subskills.py`, which auto-registers it here
and in the `cmo` record's `sub_skills` inside `config/skills.json`. Registration is derived,
not typed by hand.
